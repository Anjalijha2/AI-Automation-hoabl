## 6. Pre-conditions

### For all happy-path TCs (UI_001–UI_005, FUNC_001–FUNC_005, E2E_001, VAL_001–VAL_007)
- Clean browser session (no `storageState` loaded) OR fresh incognito context
- UAT environment reachable: `https://uat-web.xrportal.in/admin`
- Master mobile `8888888888` pre-provisioned in user table (BRD §11.3) — already true on UAT

### For session-state TCs (E2E_002)
- Valid `automation-repository/fixtures/.auth/admin.json` storageState file < 24 hours old
- File generated by prior successful run of E2E_001 (or `npm run auth:setup`)

### For revoked-user TC (NEG_002)
- DB seed: a pre-provisioned admin record with `isActive=false`
- Mobile of that record known to tester
- `[MANUAL-ONLY]` — requires DBA assistance

### For lockout test (NEG_003)
- Master mobile `8888888888`
- No prior wrong-attempt counter state in browser (fresh session)

### For Re-Send timer (NEG_004, FUNC_006)
- OTP screen freshly loaded (timer just started)
- FUNC_006 additionally requires wait through full countdown

### For destructive / known-defect TCs (EDGE_002)
- Captured JWT from a successful login
- Ability to issue API calls with `Authorization: Bearer <jwt>` header (e.g. via curl, Postman, or Playwright `request.newContext`)

## 9. Data Risks / Notes

- **No PII recording:** Master mobile `8888888888` and master OTP `258369` are documented internal credentials, not real user data. Real mobile numbers used in `[MANUAL-ONLY]` TCs must NOT be committed to source.
- **JWT capture for EDGE_002:** captured JWTs are sensitive — handle as secrets; do not log to test reports; do not commit captured tokens; rotate by completing a fresh login at session end.
- **Re-Send burst (EDGE_001):** even though no backend rate limit exists, do not run thousands of requests on UAT — could affect SMS-provider billing if path leaks to live dispatcher.
- **Cross-portal master OTP:** the cp/user `masterOtp` (BRD §11.2) is a different value — do NOT attempt to use `258369` for non-admin portals; out of Admin Portal scope.
