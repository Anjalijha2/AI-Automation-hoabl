Customers Module

Admin Portal — Main operational dashboard for buyer registrations

Audience: Admin / SM Admin URL: /admin/customers Last Updated: 2026-05-22 14 Features

Overview

The Customers page is the main operational dashboard for the admin team. It lists every buyer registration in the system with live KPI counts at the top and a searchable, filterable registration table below. From here you can cancel units, refund registrations, approve home loans, swap units, update parking, view milestone schedules, record offline payments, assign units, run bulk cancellations, and download an Excel export of all registrations.

This page loads automatically after login. You can also reach it from the left sidebar → Customers, or directly at /admin/customers.

Page Layout (At a Glance)

  1. KPI Cards (top row, six tiles) — live counts.
  2. Controls bar — Cancel Bulk Units, Filter, Refresh, Download, Search by Phone.
  3. "Allocation Opened" banner — static label rendered as the table title.
  4. Registration table — one row per sub-registration; Actions column has a trash icon + three-dot menu.
  5. Pagination — bottom of table.
Read-only — no data change
Reversible write — can be undone
Irreversible — permanent, no undo

Features

1. Registration Dashboard (KPI Cards + Table)

READ

What it does. Gives a real-time at-a-glance view of all buyer registrations across the active project. The six KPI cards summarise totals; the table below lists every registration record with status, KYC, home loan, and unit-allotment information.

Preconditions

  • Admin session.
  • Default landing route after login.

Step-by-step

  1. Log in. The Customers dashboard loads automatically.
  2. Read the six KPI tiles at the top: Registered (sum of Booked Offline + Booked Online + Registered + Inactive), Inactive Registrations, Cancelled Registrations, KYC Pending (Booked), Confirmed (Paid + KYC), Active Towers.
  3. Below the KPIs, the table heading shows the true total (e.g. "9,672 Registration Records").
  4. Each row shows: Registration Details, Growth Partner, Phone, Home Loan Details, Confirmation Number, Allotted Unit, Allocation Status, Confirmation, Process Status, and Actions.
  5. Sorted descending by created date — newest at top.
Note (Corrected 2026-05-21)

KPI tiles are computed by a separate aggregate query and always reflect global project totals. Applying a filter, search, or sort to the table does NOT recompute the KPI numbers. The allotedCount KPI is commented out in source — there is no "Alloted" tile.

Warning

The "Allocation Opened" label above the table is a static hardcoded label — it does NOT indicate whether an allocation campaign is actually open. Verify campaign state in the Allocation module.

2. Search by Phone

READ

What it does. Filters the registration table down to records matching a buyer's phone number.

Corrected 2026-05-21 — phone-only search

This field performs a LIKE %value% substring match against User.phone ONLY. Despite the label, it cannot find a buyer by name, registration number, confirmation number, unit number, or tower name — those branches are commented out in source.

Preconditions

  • You know the buyer's phone number.

Step-by-step

  1. Locate the Search by Phone field at the top right of the table.
  2. Type the phone number (or any substring of it).
  3. The table auto-filters to matching records.
  4. To restore the full list, clear the field.

Result. For lookups by name, registration number, confirmation number, unit, or tower — use the Filter panel instead.

4. Pagination

READ

What it does. Lets you move between pages and change how many rows show at once.

Step-by-step

  1. Scroll to the bottom of the table.
  2. Adjust page size: click the dropdown ("10 / page" by default) → choose 10 / 20 / 50 / 100.
  3. Navigate: click the page number, or use Previous / Next arrows.
  4. Pagination text reads "1-10 of N items" (N = true total).

5. Refresh Table

READ

What it does. Reloads the table data from the server without leaving the page.

Step-by-step

  1. Click Refresh above the table.
  2. A brief loading state shows; then the table redraws.

Result. The table reflects the latest server state — useful after another admin made a change.

6. Cancel Unit (Booked rows)

IRREVERSIBLE

What it does. Cancels just the allotted unit for a Booked row. Operates at RegistrationUnit level — parent Registration and sibling sub-registrations are not touched. No refund is issued.

Eligibility

  • Row's Allocation Status = Booked Online or Booked Offline.
  • Internally: status = WINNER AND allocationTransactionId is present.
  • Off-system CRM Activity cleanup (Token, Form, Booking) and Mavis booking deletion must be done before triggering this.

Step-by-step

  1. Locate the Booked row in the table.
  2. Hover the trash icon in the Actions column — tooltip reads "Cancel Unit".
  3. Click the trash icon. Modal opens with two attestation checkboxes: Activity - Token, Form, Booking deleted and Mavis - Booking entry deleted.
  4. Tick both checkboxes — Submit button enables only when both are ticked.
  5. Click Submit.
Result

Toast: "Unit cancelled successfully". The allotted unit is released; the row reflects the cancellation; no refund issued.

Warning — Irreversible

The attestation checkboxes are admin self-declarations — the backend does NOT auto-delete the CRM Activity or Mavis booking. Failing to perform those steps first leaves inconsistent state.

7. Cancel Registration (Registered / Waitlisted rows, ₹999 refund)

IRREVERSIBLE

What it does. Cancels a Registered or Waitlisted record (no unit allotted yet) and refunds the ₹999 registration confirmation amount to the buyer.

Eligibility

  • Row's Allocation Status = Registered or Waitlisted.
  • No unit allotted; only the ₹999 confirmation fee was paid.

Step-by-step

  1. Locate the Registered/Waitlisted row.
  2. Hover the trash icon — tooltip reads "Cancel Registration".
  3. Click the trash icon. A confirmation popup shows unit details + refund amount ₹999.
  4. Click the red Cancel Registration button.
Result

Toast: "Registration refunded successfully". Row status → Cancelled. ₹999 refunded to buyer's original payment method.

Warning

Permanent and irreversible. Do not use on a Booked row — that is "Cancel Unit" (Feature 6), which does not refund.

8. Home Loan Approval

WRITE

What it does. Lets an admin manually approve a buyer's home loan application, making the HOME_LOAN offer discount eligible during the next allocation campaign.

Eligibility

  • Buyer must have initiated a home loan application (loanType = self or easiloan).
  • Current loanApprovalStatus is pending or null.
  • Always available in the three-dot menu regardless of row status.

Step-by-step

  1. Find the buyer's row.
  2. Click the three-dot (…) menu in the Actions column.
  3. Select Home Loan Approval.
  4. In the modal, flip the toggle to ON.
  5. Click Save / Submit.
Result

RegistrationHomeLoan.loanApprovalStatus → admin_approved; approvalSource → admin. HOME_LOAN offer becomes eligible for next allocation campaign. No buyer notification is dispatched.

Source-verified (2026-05-23)

registration-unit.service.js updateHomeLoanDetails (lines 349–387) — zero sendSms / sendWhatsapp / sendEmail calls. FRD claim of SMS/WhatsApp was incorrect.

9. View Milestones (Booked rows)

READ

What it does. Opens a dedicated milestone payment schedule page for the selected allotted unit, showing each milestone, dues, GST, principal, total amount, outstanding, payment status, and any recorded transactions. An Offline Payment action is available for payable rows.

Eligibility

  • Row's Allocation Status = Booked Online or Booked Offline.
  • Buyer must have submitted KYC — otherwise the milestone table is empty.

Step-by-step

  1. Locate the Booked row.
  2. Click the three-dot (…) menu → View Milestones. Navigates to /admin/milestone?rn=<rn>&uid=<uid>.
  3. Read the Payment Status column: Pending (clock icon), Partial Payment (card icon), Paid (check-circle icon), empty = future date, - = zero-amount milestone.
  4. Click View in the DETAILS column to see a payment breakdown drawer.
  5. Click Offline Payment in the ACTION column to record an offline collection (see sub-flow).
  6. Click Back to Customer Listing (top-left) to return.

Offline Payment Sub-flow

The drawer captures 11 fields (POST to apiUrls.adminMilestonePaymentOffline):

FieldRules
Registration NumberAuto-injected, read-only
AmountMust be > 0; for GST must equal gstOutstanding exactly (±0.01)
Payment MethodNEFT / Cheque / Cash / CC / DC / UPI
Transaction IDRequired — bank/cheque reference
Transaction Date & TimeFormat YYYY-MM-DD HH:mm:ss; cannot be in the future

Warning

View Milestones triggers no buyer-facing notification. An empty milestone table on a Booked row almost always means KYC has not been submitted yet.

10. Unit Swap (Booked rows)

IRREVERSIBLE

What it does. Reassigns a buyer's already-allotted unit to a different unit within the project.

Eligibility

  • Row Allocation Status = Booked Online / Booked Offline.
  • No allocation campaign is currently OPEN — backend blocks with 400 "Cannot swap unit when campaign is active".
  • No active Mavis booking row exists — must be deleted externally first.
  • Target unit status = AVAILABLE or RESERVED.

Step-by-step

  1. Before opening the modal, delete CRM Activity records (Token, Form, Booking) and the Mavis booking entry.
  2. Locate the Booked row → click three-dot menu → Unit swap.
  3. The modal opens. Pick a Tower then pick a Unit.
  4. Tick both attestation checkboxes: "Activity deleted" and "Mavis booking deleted".
  5. Click Submit.
Result

Toast: "Unit swapped successfully". Old unit → RESERVED; new unit → BOOKED. RegistrationUnit fields updated. KYC flags reset.

Warnings

Milestone schedule is NOT auto-regenerated after a swap — known backend limitation. No buyer SMS/WhatsApp/Email is dispatched. Unit dropdown lists units of any typology — no filter on apartment type.

11. Update Parking Details (Booked rows)

WRITE

What it does. Enables, updates, or disables additional parking on a buyer's booked unit. System computes total parking amount that flows into the buyer's costing.

Eligibility

  • Row Allocation Status = Booked Online / Booked Offline.

Step-by-step

  1. Locate the Booked row → click three-dot menu → Update Parking Details.
  2. The Parking Details modal opens with an Additional Parking Enabled toggle.
  3. To enable/update: flip toggle ON → enter Parking Count (1–500) and Parking Amount. Preview shows Total = Count × Amount.
  4. To disable: flip toggle OFF. Both Count and Amount are immediately cleared (set to null).
  5. Click Submit.
Result

Toast: "Parking details updated successfully". RegistrationUnit.isParkingSelected, parkingCount, parkingAmount are written. Parking pool for the typology is adjusted.

Warnings

No buyer SMS/WhatsApp/Email dispatched. Disabling parking clears both Count and Amount — no undo in-app. Backend rejects with 400 "No change in parking count" if delta = 0.

12. Download Export

READ

What it does. Exports registration records as an Excel file named RegistrationData.xlsx with 17 columns.

Step-by-step

  1. Click the Download button (top right area).
  2. The file downloads automatically to your browser's default download folder.
  3. Open in Excel.
Corrected 2026-05-21 — export respects active filters

Active filters ARE respected by the export. No active filter = full export. Active filter = filtered export across all pages. Click Reset Filters before Download if you want all records.

13. Assign Unit / Offline Booking (Registered rows)

IRREVERSIBLE

What it does. Assigns a unit to a Registered buyer and records an offline booking payment in a single transaction. Used when a buyer pays via bank transfer, cheque, UPI, or cash outside the online gateway.

Eligibility

  • Row Allocation Status = Registered.
  • No unit currently allotted.
  • Target unit status = AVAILABLE or RESERVED.

Step-by-step

  1. Find the eligible Registered row → click three-dot menu → Assign Unit.
  2. Pick a Tower then pick a Unit (only Available/Reserved units shown).
  3. Enter payment details: Transaction ID, Mode of Transaction (UPI / NEFT-RTGS / Cheque / Cash), Booking Amount, Transaction Date.
  4. Optionally upload Payment Proof (image or PDF).
  5. Click Submit.
Result

Offline payment recorded. Unit status → BOOKED. Mavis + LSQ synced. Buyer receives Kaleyra WhatsApp (template: congrates_payment_success_27sept) + Kaleyra SMS (ALLOTMENT_PAYMENT_SUCCESS, +91 numbers only). No email sent.

Source-verified (2026-05-23)

registration-unit.service.js lines 877–885 calls allocationNotificationService → allocation.service.js lines 1816–1832. WhatsApp + SMS confirmed. Email NOT dispatched. FRD claim of "Email + WhatsApp" was partially incorrect.

Warning

If the unit becomes unavailable between selection and submit, error: "Selected unit is no longer available. Please choose another unit." No booking is created.

14. Bulk Cancel Units

IRREVERSIBLE

What it does. Cancels multiple sub-registrations at once — useful for cleanup on test data or bulk corrections.

Step-by-step

  1. Click the Cancel Bulk Units button above the table.
  2. The bulk cancel interface opens. Select the sub-registrations to cancel.
  3. Confirm.
Warning — Irreversible

Permanent and irreversible. Recommended only for test records or after explicit business sign-off.
